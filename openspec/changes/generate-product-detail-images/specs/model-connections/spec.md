# Spec Delta

## Purpose

把已有的服务商和 SK 设置扩展为按文本视觉理解与图片生成能力选择模型的连接配置，使用户能知道哪些模型可执行当前操作并得到可诊断的失败信息。

## ADDED Requirements

### Requirement: 分别配置模型角色
系统 SHALL 分别设置“视觉理解模型”和“图片生成模型”，展示每个预设服务商在当前实现中支持的角色；用户 SHALL 能编辑 Base URL 与准确的模型 ID。系统 MUST 不把仅支持文本的配置当作图片生成配置使用。

#### Scenario: 选择可用角色
- **WHEN** 用户在设置页选择一个已实现的视觉或生图服务商
- **THEN** 页面显示该角色的接口地址、模型 ID、SK 状态和能力说明

#### Scenario: 模型能力不足
- **WHEN** 用户尝试使用未配置图片输入能力的模型进行原图分析
- **THEN** 系统阻止任务启动或返回可操作错误，不静默退回纯文本分析

### Requirement: 模型连接验证
系统 SHALL 提供按角色的连接测试；视觉测试 MUST 验证图片输入，生图测试 MUST 验证所配置接口可产出图片，且测试前 SHALL 提示可能产生费用。测试结果 SHALL 区分鉴权、模型不可用、能力不支持、限流和网络错误。

#### Scenario: 视觉模型测试成功
- **WHEN** 用户输入有效 SK 和支持图片输入的模型并点击视觉测试
- **THEN** 系统发送测试图片并显示成功状态及实际响应模型

#### Scenario: 生图模型测试失败
- **WHEN** 服务商返回不支持参考图、模型不可用或鉴权失败
- **THEN** 页面显示对应的错误类别和服务商原始错误摘要，不标记连接成功

### Requirement: 密钥与配置边界
系统 MUST 将 SK 只保存在本机服务进程内存中，不通过配置读取接口返回明文，不写入浏览器持久存储或任务文件。服务重启后系统 SHALL 提示重新输入 SK；缺少 SK 的既有任务 SHALL 暂停进一步外部调用，保留已有结果。

#### Scenario: 读取配置
- **WHEN** 页面读取已保存的模型配置
- **THEN** 系统只返回服务商、接口地址、模型 ID 和是否有 SK，不返回 SK 内容

#### Scenario: 服务重启后恢复任务
- **WHEN** 本机服务重启且有未完成任务
- **THEN** 任务保留已有结果并进入等待凭据状态，用户重新配置 SK 后才能继续
