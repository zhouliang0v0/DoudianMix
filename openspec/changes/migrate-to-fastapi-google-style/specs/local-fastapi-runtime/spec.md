# Spec Delta

## Purpose

使本机商品详情图生成器能够由 Python 3.11 服务独立运行，同时让迁移前保存的草稿、任务和成品图继续可用，让现有页面及接口调用方保持原有操作方式。

## ADDED Requirements

### Requirement: Python 3.11 本机服务可独立运行

系统 SHALL 提供使用 Python 3.11 启动的本机服务，并在最终切换后无需 Node 服务进程提供页面、API 或生成任务。

#### Scenario: 从干净检出启动

- **WHEN** 用户按项目文档在 Python 3.11 环境安装依赖并启动服务
- **THEN** 首页、设置页、结果页和现有 `/api/*` 接口在 `127.0.0.1:8765` 可访问，启动不要求运行 `npm start`

#### Scenario: 不接受错误 Python 版本

- **WHEN** 用户用 Python 3.9 尝试安装或启动最终服务
- **THEN** 环境约束明确指出需要 Python 3.11，且不会在不兼容解释器下运行任务

### Requirement: 现有 HTTP 契约保持兼容

系统 SHALL 维持现有草稿、模型设置、AI 帮写、任务、结果和旧文本兼容接口的路径、请求字段、响应字段、成功状态码、可识别错误结构和图片/ZIP 类型。

#### Scenario: 页面使用原有 API 完成操作

- **WHEN** 现有页面按既有请求格式创建草稿、上传图片、配置模型并创建任务
- **THEN** 服务返回页面当前使用的 `draftId`、`assetId`、`previewUrl`、`jobId` 等字段及既有成功状态码

#### Scenario: 无效输入与失败响应

- **WHEN** 客户端上传无效图片、请求不存在的任务或提交无效模块
- **THEN** 服务返回与既有契约一致的 HTTP 状态及包含 `error` 和适用时 `code` 的 JSON，页面能直接展示错误

#### Scenario: 下载结果

- **WHEN** 用户下载已完成的模块图片或任务 ZIP
- **THEN** 服务返回对应图片类型或 ZIP 内容，成功模块、文案及失败清单与迁移前一致

### Requirement: 既有文件数据保持可读与可恢复

系统 SHALL 读取迁移前 `data/drafts/` 和 `data/jobs/` 中的有效草稿、任务及图片，并沿用现有文件目录、JSON 字段、时间戳单位和任务状态语义。

#### Scenario: 读取旧草稿和已完成任务

- **WHEN** 服务使用迁移前创建的数据目录启动
- **THEN** 用户可恢复草稿预览、查看旧任务和已完成结果，无需重新上传原图或重新生成已完成模块

#### Scenario: 恢复迁移前中断的任务

- **WHEN** 旧数据中存在 `queued`、`analyzing`、`planning` 或 `generating` 任务
- **THEN** 服务将任务置为 `waiting_credentials`，把运行中模块恢复为 `pending`，保留已完成图片，并在用户重填与快照一致的模型配置后继续

#### Scenario: 任务元数据写入中断

- **WHEN** 服务在更新任务元数据期间中断
- **THEN** 重启后 `job.json` 仍是完整可解析的版本，已完成图片不会因半写入而遗失

### Requirement: 模型密钥与商品图发送边界保持一致

系统 SHALL 仅在服务进程内存中保存 SK，且只在用户触发相应 AI 操作时把商品原图和资料发送给所选服务商。

#### Scenario: 仅上传商品图片

- **WHEN** 用户上传原图或打开模型设置页而未触发 AI 帮写或生成
- **THEN** 商品图片不会发送给外部模型服务商

#### Scenario: 配置与任务数据不泄露 SK

- **WHEN** 用户读取公开配置、任务 JSON 或下载 ZIP
- **THEN** 响应和持久化文件不包含 SK；服务重启后提示用户重填

#### Scenario: 能力测试使用内置测试图

- **WHEN** 用户在设置页运行视觉或生图能力测试
- **THEN** 请求使用内置测试图，成功状态仅在对应角色实际支持该图片能力时标记

### Requirement: 生成任务行为保持一致

系统 SHALL 串行执行任务与模块，保留成功模块结果，并支持现有的取消、失败模块重试、导出和删除操作。

#### Scenario: 局部失败和单模块重试

- **WHEN** 多模块任务有模块失败而其他模块成功，用户重试其中一个失败模块
- **THEN** 服务只重新请求该模块，不重做成功模块或其他失败模块，已有成品图保持可访问

#### Scenario: 取消与删除

- **WHEN** 用户取消进行中的任务或删除任务
- **THEN** 取消阻止后续模块生成并保留已完成结果；删除清除该任务与关联资产，使对应读取接口不再返回数据
